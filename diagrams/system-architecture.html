eshop-full — system architecture

Twenty-one projects, four layers — fifteen done, six still to come.

This is the target shape, not a claim that it already runs end-to-end — eShop.AppHost (the Aspire orchestrator every service and container dependency registers with) is deliberately the last project added, since it can't meaningfully exist until the things it orchestrates do. Migration order is foundation-first: shared/foundation projects, then domain APIs, then background workers, then the frontends, then eShop.AppHost, then tests/ and build/. See Event Flow for how the foundation layer's pieces actually talk to each other today.
